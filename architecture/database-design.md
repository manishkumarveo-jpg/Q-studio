# Database Design

+## Relational model

Core tables: users, sessions, workspaces, workspace_members, projects, folders, assets, asset_versions, collections, collection_assets, metadata_fields, metadata_values, comments, comment_replies, annotations, review_links, approval_requests, approval_events, shows, episodes, source_screenshots, ingestion_batches, ingestion_jobs, qc_items, activity_events, notifications, upload_intents, transfer_jobs.

All tenant resources carry workspace_id, opaque IDs, created_at, updated_at, actor fields, and nullable deleted_at where recoverability applies. FKs enforce parent relationships; active membership and normalized-name uniqueness prevent ambiguity. Indexes cover scope+updated time, asset/current version, episode/sort tuple, token hashes, job idempotency keys, and session token hashes.

Search and collections (Phase 04 mock → Phase 06 D1): collection_assets is a (collection_id, asset_id) join with a composite primary key, so membership is idempotent and never copies assets. metadata_values is keyed (asset_id, field_id); a deleted metadata_field is soft-deleted (deleted_at) and its values stay readable. The Phase 06 search query scopes by workspace_id first, joins assets → projects/folders for visibility (non-archived), applies kind/project/collection/field filters as AND predicates against indexed columns (assets(workspace_id, kind), collection_assets(asset_id), metadata_values(field_id, value)), and orders by normalized name then ID. Free-text matching starts as a bounded LIKE over name and metadata values; FTS5 is evaluated only if measured latency requires it. Saved filters and view preferences remain per-browser until a later phase adds a server-side preference.

Identity (Phase 05, `database/migrations/0001_auth.sql`): workspaces; users (`username_normalized` UNIQUE, Argon2id PHC `password_hash`, `must_change_password`); workspace_members (PK workspace_id+user_id, role CHECK, per-workspace `status` active/disabled, created_by/updated_by); sessions (SHA-256 `token_hash` UNIQUE, expires_at = created +12 h, revoked_at/revoked_reason, partial index on active sessions per user); login_throttle (fixed 15-minute window per `user:`/`ip:` key, upserted atomically before verification); bootstrap_state (single row `id = 1`, so a repeat or concurrent bootstrap fails its transaction); audit_events (action, outcome success/denied/failed, request_id, actor/workspace/resource IDs, never credentials or tokens). Each session lookup joins the active membership, so disabling a member denies their open sessions immediately. Rollback before production data exists: drop the seven tables. After launch, changes are additive migrations only. Throttle rows are not pruned yet (Phase 19).

QC items keep original/edited text, original/normalized timecodes, frame-rate, sort tuple, source screenshot/crop references, confidence, verification state, status, fixed, priority, assignee and optimistic version. See [../diagrams/database-erd.md](../diagrams/database-erd.md).
